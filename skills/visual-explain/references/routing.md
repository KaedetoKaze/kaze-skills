# 表示路由

先确定理解目标，再比较候选表示。路由结果是“最小充分表示”，不是视觉丰富度最高的表示。

## 一、判断是否需要视图

以下情况通常有视觉增益：

- 多个对象之间存在不易用一句话说清的连接、包含或依赖。
- 顺序、分支、循环、状态迁移或因果链是主要信息。
- 数值的大小、趋势、分布或二维权衡比单个数值更重要。
- 用户必须定位原图中的区域、路径、差异或证据。
- 参数变化或用户操作产生的结果是理解重点。

以下情况优先使用文字：

- 一句话即可回答的定义或事实。
- 只有一个结论，且没有需要观察的结构或变化。
- 图形只会把短句重新装进方框。
- 当前环境无法可靠呈现候选视图，而替代形式也不能保留其语义。

## 二、按认知任务产生候选表示

### 顺序、逻辑与运行过程

- 少量步骤或简单条件：编号列表、伪代码。
- 调用层级：ASCII 调用树。
- 多分支业务过程：流程图。
- 生命周期与允许的迁移：状态图。
- 多参与者随时间交换消息：时序图。

### 组成、层级与依赖

- 纯包含关系：缩进树或组件树。
- 文件或目录结构：文件树。
- 少量组件及其连接：Mermaid 或简洁 SVG。
- 多层系统边界、分组或交叉连接：结构图。
- 变更前后结构：并排结构图或聚焦 diff。

### 比较与选择

- 少量对象、少量精确属性：Markdown 表格。
- 数量级或类别大小：条形图、点图。
- 随时间变化：折线图；时间点很少时也可用表格。
- 两个数值维度的权衡：散点图或象限图。
- 分布：直方图、箱线图或密度图。
- 定性结构差异：并排图或对照树。
- 决策条件：决策树或选择矩阵。

### 因果、反馈与影响

- 单向短链：箭头链或编号因果链。
- 多个共同原因或结果：因果图。
- 存在反馈回路：回路图或系统图。
- 只能证明相关而不能证明因果：使用中性连接和明确文字，不画因果箭头。

### 空间证据与原始图像

- 指认区域或对象：原图叠加轮廓、标签或引线。
- 展示路径：原图叠加轨迹，并标明方向和起止点。
- 对比局部差异：并排裁切或原图上的差异标注。
- 需要真实地图语义：使用可用的地图能力；没有地图能力时不要用示意图冒充地图。

### 抽象概念与类比

- 关系可以符号化：简洁图解或信息图。
- 需要场景、氛围或直觉类比：生成式插图。
- 概念同时含有精确标签：插图与确定性文字层分开制作。

### 变化与探索

- 只需展示几个关键状态：小倍图或并排静态帧。
- 连续变化本身重要：动画。
- 用户需要调整参数并观察结果：交互视图。
- 交互不能增加可理解的新信息：使用静态视图。

## 三、选择最小充分表示

在候选表示之间依次比较：

1. 哪一种能最直接显露理解目标？
2. 哪一种需要最少的视觉语法和操作说明？
3. 哪一种能最可靠地保持证据与数值精度？
4. 哪一种可由当前宿主直接交付？

复杂表示必须证明其额外复杂度带来了额外理解。ASCII 调用树可能优于 SVG；表格可能优于图表；静态帧可能优于交互控件。

## 四、组合多个视图

只有单一视图无法同时表达两个相互独立的重点时才组合视图。每个视图承担一个明确问题，并用一句过渡说明二者关系。避免连续堆叠表达相同结论的图。

组合示例：

- 系统结构图 + 一条关键请求的时序图。
- 趋势图 + 解释异常点的原图标注。
- 生成式概念插图 + 独立的确定性标签图层。
