# 交互与动态表达

只有当变化、探索或用户操作本身构成理解目标时，才使用动画或交互。能用少量静态帧解释的内容优先使用静态视图。

## 适用判断

交互有价值的典型情况：

- 用户需要改变参数并观察输出如何变化。
- 信息密度较高，需要筛选、聚焦或按需展开。
- 状态转换、时间演化或空间运动是主要内容。
- 多个合理视角需要由用户主动切换。

以下情况保持静态：

- 控件只切换装饰效果。
- 所有状态可以在少量并排视图中完整表达。
- 当前宿主无法可靠运行或预览交互内容。
- 交互会隐藏主要结论，用户必须操作后才能知道图想表达什么。

## 状态与控制

- 为每个控件定义输入范围、默认值和它影响的视觉变量。
- 初始状态直接展示主要结论，而不是空白画布。
- 操作后立即给出可见反馈；加载或计算需要等待时显示状态。
- 控件标签使用领域含义，不使用内部变量名代替用户语言。
- 限制无意义或无效组合，并解释边界。
- 同一个状态只能有一个事实来源，避免图形、数值标签和说明不同步。

## 动画

- 动画表达顺序、方向、因果或连续变化，不用于持续吸引注意。
- 提供暂停、重播或手动步进方式；较长过程显示当前阶段。
- 保持对象恒常性：同一对象在不同状态间维持可识别的位置、颜色或形状。
- 尊重减少动态效果的系统偏好，并提供静态终态或关键帧。

## 可访问性与替代

- 控件支持键盘操作、清楚焦点和可读标签。
- 不依赖悬停或拖拽才能访问唯一信息。
- 为当前状态提供文字或数值摘要。
- 提供静态等价视图；宿主无法运行交互时直接交付该视图。

## 完成标准

- 用户不操作也能理解主题和起始状态。
- 每次操作都会产生与理解目标直接相关、可解释的变化。
- 控件、图形与数值始终同步，无失效状态或越界内容。
- 键盘、窄屏和减少动态效果模式下仍能获得主要结论。
- 移除交互后，静态替代仍保持核心事实和解释目标。
