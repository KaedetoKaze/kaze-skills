# 视觉解释

用一个最小充分视图帮助用户理解当前主题。视觉是解释手段，不是任务目标。

## 第一原则

**选择最小充分视图。** 只有当视图能比 1—3 段简洁文字更清楚地呈现关键关系、结构、比较、变化或证据时，才使用视觉表达。轻量表示本身就是正确答案，不是低级降级。

**承载证据的信息必须保持确定性。** 精确数值、文字标签、拓扑、测量几何、事实性空间关系和用户原始视觉证据使用确定性渲染。生成式图像只承担类比、氛围和非证据性概念解释。

## 执行过程

1. **定义理解目标。** 用一句话明确“用户看完后应该理解什么”。完成标准：这句话只包含一个主要认知重点。
2. **判断视觉增益。** 比较简洁文字与视觉表达；视觉没有明显增益时，直接使用文字。完成标准：能够指出视图将显露的关系、结构、比较、变化或证据。
3. **识别信息约束。** 区分证据性内容、精确数据、用户原图与仅用于解释的概念素材。完成标准：所有必须保持原貌或精确对应的信息都已标出。
4. **产生候选表示并选择。** 先读 [references/routing.md](references/routing.md)，再选择复杂度最低但足以表达重点的表示。不要把认知任务机械映射成唯一图形类型。
5. **适配宿主能力。** 以当前系统、工具列表或用户明确提供的能力为准。理想表示不可用时，寻找语义等价的替代形式。
6. **渲染并检查。** 读取所选表示对应的参考文件，只执行相关分支的规则和完成标准。

## 按需参考

- 生成图、图表、SVG、HTML 或图像时，读取 [references/visual-language.md](references/visual-language.md)。纯文字、Markdown 表格或简单 ASCII 不必读取。
- 使用 ASCII、伪代码、树、Mermaid、数据图表、SVG 或静态 HTML 时，读取 [references/deterministic-rendering.md](references/deterministic-rendering.md)。
- 标注用户原图或生成解释性插图时，读取 [references/image-rendering.md](references/image-rendering.md)。
- 只有当变化、探索或用户操作本身构成理解目标时，读取 [references/interaction.md](references/interaction.md)。

每次只读取当前表示需要的参考文件。

## 通用完成标准

交付前确认：

- 不依赖长篇正文也能识别主要结论。
- 表示的复杂度没有超过理解目标所需。
- 标签、方向、图例和连接关系无歧义。
- 事实、数值、比例和原始证据没有被装饰性处理改变。
- 输出能在当前宿主中实际查看；不能可靠渲染时已换用可用表示。
- 视觉之后只补充理解所需的简短说明、假设或来源信息。

## 范围边界

本 Skill 负责选择并创建解释某个思想所需的单个视图或少量互补视图。完整演示文稿、报告、网站、Dashboard、品牌系统或长篇信息图由相应制品工作流主导；本 Skill 只为其中需要解释关系或证据的局部提供视图。
