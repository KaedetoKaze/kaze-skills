# 格式渲染注意事项

## 优先保留的语义

- 标题层级、段落、粗体、斜体、删除线、行内代码。
- 有序/无序列表与任务列表。
- 表格的单元格文本、表头和行列结构。
- 代码块语言标识。
- 引用块、callout、图片题注、来源链接。
- 飞书文档 URL、标准 Markdown 链接、Obsidian wikilink 和外部链接。

## 常见差异

| 内容 | 注意事项 |
| --- | --- |
| Frontmatter | 飞书无原生 YAML frontmatter；导出到飞书时通常省略，或转成文档开头的元信息表。 |
| Wikilink | 仅 Vault 模式处理；飞书不理解 `[[笔记]]`，导出时保留为纯文本或改为可访问链接。仓库模式不得新增 wikilink。 |
| 块引用 | Obsidian `^block-id` 与飞书 block id 不是同一体系；不要假装可无损同步。 |
| Callout 折叠 | Obsidian 的 `+`/`-` 折叠状态可能无法在飞书完全复现；不支持或转换不完整时保持本地原样并报告差异。 |
| 表格 | 合并单元格、复杂样式、列宽和颜色可能丢失；复杂表格优先用飞书 XML。 |
| 图片分栏 | 飞书中用于并排展示图片的分栏，导入 Obsidian 时必须检查并列关系；默认用 Markdown 表格代替，而不是顺序展开图片。 |
| 飞书白板 | 默认 Markdown 导出通常不能可靠包含白板内容；若 Mermaid/PlantUML 可完整复现，保留代码块更好，否则按 `image-handling.md` 导出 SVG。 |
| 任务列表 | 勾选状态应保留；负责人、日期等飞书增强属性可能需转成普通文本。 |
| 代码块 | 语言名尽量保留；飞书高亮效果与 Obsidian 主题可能不同。 |
| 高亮 | 导出飞书时可转为背景色或普通强调，反向导入时尽量转回 `==...==`；无法保真时保持本地原样并报告差异。 |
| 颜色 | 飞书文字色、背景色在 Markdown 中没有标准表达；必要时用 HTML 或说明保留。 |
| 折叠标题 | 飞书折叠块与 Markdown 标准不一致；导入 Obsidian 时可转为标题加 callout 或普通列表。 |
| 嵌入资源 | 飞书 sheet、bitable、whiteboard 等资源块不能只保留标签；应提取 token 并使用当前环境可用的对应工具处理，或明确说明未下钻。嵌入 PPTX、附件或预览不能保留 `figure`／`source`／`cite` 等原始标签；仅文字同步时保留可读文字说明并注明文件本体未同步。 |
| 飞书分栏 | 不保留 `grid`／`column` 标签；每个连续分栏组转换为一张 Markdown 表格，表头与分隔行必须独占行。 |
| 飞书 Callout | 不保留 `<callout>` 标签；转换为 `> [!type]`，所有内容行加 `>`，并确保 Callout 前后各有空行。 |

## 写入选择

- Vault 与仓库文档都通过官方 `lark-cli` 或功能等价的飞书文档 API 客户端同步；Vault 模式先解析 wikilink、Callout、高亮等专有语法。
- 创建或整段导入飞书：用户给 `.md` 或明确要 Markdown 时用 Markdown；否则优先 XML。
- 精准编辑飞书已有内容：优先 XML 和 block 级命令。
- 从飞书导入本地：保真优先 XML，速度优先 Markdown；遇到 callout、资源块、图片、白板或复杂表格时改用 XML 或补充 fetch。仓库模式写标准 Markdown，Vault 模式才转换 Obsidian 专有语法。

## 复核清单

- 标题层级没有整体偏移。
- 列表缩进和任务勾选状态正确。
- 表格没有错列、截断或丢失表头。
- 代码块围栏闭合，语言标识保留。
- 图片可从目标 Markdown 的实际运行环境打开，飞书中也能显示。
- 分栏图片在本地仍保留并列关系，或已说明无法保留的原因。
- 飞书白板已保留为可渲染 Mermaid/PlantUML，或按 `image-handling.md` 落盘为 SVG，并保留必要的说明文字。
- Callout 类型、标题和正文语义一致。
- 没有留下飞书临时图片 URL、本地绝对路径或无法解析的关键链接。
